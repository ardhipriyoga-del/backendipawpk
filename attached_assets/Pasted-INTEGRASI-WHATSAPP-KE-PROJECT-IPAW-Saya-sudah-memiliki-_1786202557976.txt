INTEGRASI WHATSAPP KE PROJECT IPAW

Saya sudah memiliki project IPAW yang saat ini sudah berjalan di Replit.

Tugas Anda adalah MENAMBAHKAN fitur WhatsApp Gateway ke project yang sudah ada menggunakan Baileys + REST API, dengan konsep:

IPAW HTML
→ Backend IPAW
→ Baileys
→ WhatsApp

ATURAN PALING PENTING

1. JANGAN menghapus fitur IPAW yang sudah ada.
2. JANGAN mengubah database existing.
3. JANGAN mengubah struktur Google Spreadsheet existing.
4. JANGAN mengubah alur realtime existing.
5. JANGAN mengubah UI existing kecuali menambahkan elemen WhatsApp yang diperlukan.
6. JANGAN mengganti framework existing.
7. JANGAN melakukan refactor besar terhadap project.
8. Jangan membuat project baru.
9. Gunakan struktur dan teknologi backend yang SUDAH digunakan project IPAW.
10. Sebelum melakukan perubahan, periksa seluruh struktur project terlebih dahulu.
11. Pertahankan seluruh fungsi existing agar setelah integrasi WhatsApp project tetap berjalan seperti sebelumnya.

⸻

TUJUAN

Saya ingin IPAW dapat mengirim WhatsApp tanpa membuka WhatsApp Web secara manual.

Konsep penggunaan:

1. Admin membuka menu Pengaturan WhatsApp.
2. IPAW menampilkan status koneksi WhatsApp.
3. Jika belum terhubung, tampilkan QR Code.
4. User melakukan scan QR menggunakan WhatsApp.
5. Setelah berhasil scan, session WhatsApp disimpan secara persistent.
6. Setelah itu user TIDAK perlu scan QR lagi setiap kali Replit restart, selama session masih valid.
7. IPAW dapat mengirim pesan WhatsApp melalui tombol “Kirim WhatsApp”.
8. Pengiriman dilakukan melalui backend, bukan langsung dari browser.
9. API credential/session WhatsApp tidak boleh dikirim ke frontend.

⸻

ARSITEKTUR

Buat modul terpisah:

IPAW Frontend
|
| POST /api/whatsapp/send
↓
IPAW Backend
|
↓
Baileys
|
↓
WhatsApp

Frontend tidak boleh berkomunikasi langsung dengan Baileys.

⸻

FITUR WHATSAPP

Buat modul:

/api/whatsapp/

Minimal endpoint:

GET  /api/whatsapp/status
GET  /api/whatsapp/qr
POST /api/whatsapp/send
POST /api/whatsapp/logout

Jika diperlukan, tambahkan:

GET /api/whatsapp/connection

⸻

STATUS WHATSAPP

Endpoint:

GET /api/whatsapp/status

Response contoh:

{
“connected”: true,
“phone”: “628xxxxxxxxxx”,
“status”: “connected”
}

Jika belum terhubung:

{
“connected”: false,
“phone”: null,
“status”: “disconnected”
}

Jika sedang menunggu scan:

{
“connected”: false,
“phone”: null,
“status”: “qr_required”
}

Frontend harus dapat membaca status ini.

⸻

QR CODE

Jika WhatsApp belum terhubung:

Tampilkan halaman/modal:

WHATSAPP

Status:
🔴 Belum Terhubung

Silakan scan QR Code menggunakan WhatsApp.

[ QR CODE ]

Setelah QR berhasil discan:

🟢 WhatsApp Terhubung

Nomor:
628xxxxxxxxxx

Jangan membuat QR secara manual.

Gunakan QR yang diberikan oleh Baileys.

QR hanya boleh ditampilkan kepada user yang memiliki hak akses yang sesuai.

⸻

PERSISTENT SESSION

Ini SANGAT PENTING.

Jangan meminta scan QR setiap kali server restart.

Gunakan persistent authentication state Baileys.

Session harus disimpan pada storage yang persistent di Replit.

Contoh struktur:

/data/whatsapp-auth/

atau lokasi persistent lain yang sesuai dengan environment project.

Jangan menyimpan session WhatsApp di browser localStorage.

Jangan mengirim session ke frontend.

Jika Replit memiliki mekanisme persistent storage/volume, gunakan mekanisme tersebut.

Jika environment Replit tidak menjamin filesystem persistent untuk deployment tertentu, jelaskan terlebih dahulu mekanisme persistence yang digunakan dan gunakan storage yang sesuai.

⸻

PENGIRIMAN PESAN

Buat endpoint:

POST /api/whatsapp/send

Request:

{
“phone”: “628123456789”,
“message”: “Yth. Bapak/Ibu, kami informasikan…”
}

Backend harus:

1. Validasi nomor.
2. Normalisasi nomor Indonesia.
3. Pastikan WhatsApp sudah connected.
4. Format JID WhatsApp dengan benar.
5. Kirim pesan melalui Baileys.
6. Return hasil pengiriman.

Response sukses:

{
“success”: true,
“message”: “Pesan berhasil dikirim”,
“messageId”: “…”
}

Response gagal:

{
“success”: false,
“message”: “WhatsApp belum terhubung”
}

⸻

NORMALISASI NOMOR

IPAW user mungkin memasukkan:

081234567890
+6281234567890
6281234567890

Semua harus dinormalisasi menjadi:

6281234567890

Jangan mengubah nomor internasional selain Indonesia secara sembarangan.

Buat fungsi:

normalizeWhatsAppNumber()

dan gunakan fungsi tersebut secara konsisten.

⸻

FRONTEND IPAW

Jangan mengubah UI existing.

Tambahkan fungsi JavaScript yang reusable:

sendWhatsApp(phone, message)

Contoh:

async function sendWhatsApp(phone, message) {
const response = await fetch(’/api/whatsapp/send’, {
method: ‘POST’,
headers: {
‘Content-Type’: ‘application/json’
},
body: JSON.stringify({
phone,
message
})
});

return await response.json();

}

Sesuaikan implementasinya dengan framework/struktur existing IPAW.

KEAMANAN

Sangat penting:

Jangan menyimpan API/session WhatsApp di:

* ipaw.html
* JavaScript frontend
* localStorage
* Google Spreadsheet
* URL
* query parameter

Session Baileys harus berada di backend.

Jangan expose credential/session kepada browser.

Endpoint /api/whatsapp/send harus memiliki validasi dan authentication sesuai mekanisme login IPAW yang sudah ada.

Jangan membuat endpoint terbuka tanpa proteksi jika IPAW sudah memiliki authentication.

⸻

MULTI USER

IPAW digunakan oleh beberapa user.

Pastikan:

User A mengirim WhatsApp
tidak membuat session WhatsApp baru.

Gunakan SATU koneksi WhatsApp pada backend.

Semua user IPAW menggunakan koneksi WhatsApp gateway yang sama, kecuali project existing memang memiliki konsep multi-account.

Jangan membuat QR berbeda untuk setiap user.

⸻

HANDLING CONNECTION

Baileys harus menangani:

* connected
* disconnected
* reconnecting
* QR required
* logged out
* connection replaced
* session invalid

Jika koneksi terputus sementara:

→ lakukan reconnect otomatis.

Jika session benar-benar logout:

→ status menjadi:

“WhatsApp perlu scan ulang”

→ tampilkan QR baru.

Jangan membuat reconnect loop tanpa batas yang membebani server.

Gunakan exponential backoff atau mekanisme reconnect yang wajar.

⸻

SERVER STARTUP

Saat server IPAW start:

1. Inisialisasi WhatsApp module.
2. Load session existing.
3. Coba reconnect.
4. Jika session valid → connected.
5. Jika membutuhkan QR → status qr_required.
6. Jangan mengganggu startup fitur IPAW lainnya.

Jika WhatsApp gagal connect, IPAW TETAP harus dapat digunakan.

WhatsApp adalah fitur tambahan, bukan dependency wajib untuk menjalankan IPAW.
